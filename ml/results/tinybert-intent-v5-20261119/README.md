# TinyBERT v5 实验结果（2026-11-19）

同一个四层 TinyBERT 改用独立的请求、禁止和范围重叠分数，参数量仍为 11,460,636。两组继续训练使用相同的 v4 权重、3,233 条训练、659 条验证和四轮预算。原 v4、只补数据、双路输出在开发验证上的选优分数分别为 0.4115、0.4022、0.5238，双路第 4 轮在打开新 64 条前锁定。

## 新 64 条保留题

每个场景有两种冲突说法和两个非冲突对照，共 16 组。测试覆盖同一能力的禁令冲突、不同能力、同一能力不同范围和明确改口。题目由助手撰写，人工审核 pending。

| 指标 | 原 v4 | 只补数据 | 双路输出 |
|---|---:|---:|---:|
| 判为冲突或需澄清的正确冲突题 | 4/32 | 5/32 | 19/32 |
| 将非冲突题判为冲突或需澄清 | 3/32 | 4/32 | 18/32 |
| 策略转入澄清的冲突题 | 17/32 | 25/32 | 29/32 |
| 策略误放行明确禁止能力的冲突题 | 10/32 | 4/32 | 2/32 |
| 策略误放行明确禁止能力（所有含禁令的题） | 19/60 | 4/60 | 5/60 |
| 策略放行正常、无需范围审查的请求 | 12/20 | 1/20 | 3/20 |
| 正确识别范围分开 | — | — | 0/10 |

双路输出准确定位了 14/32 条冲突题的重叠能力，整句意图头单独识别了 5/32 条，其中 3 条也准确定位了能力。最终判对冲突类别的 19 条中，有些仍找错了发生冲突的能力。「从通讯录查个号码，禁止读取通讯录」同时识别出对通讯录读取的请求与禁令，使策略拦截执行。该条也多提了联系人写入。其他错误包括把输入中的两个不同动作混成同一能力、漏掉少见措辞中的禁令，以及把分开的范围误当作重叠。双路共识别出 50/62 个请求证据和 32/60 个禁止证据。逐条见 `evaluation/new64_review.csv` 和 `evaluation/new64_dual_evidence.jsonl`。

## 已知 v4 回归和结论

旧 320 条上的 v4 数值完整复现。双路与原 v4 相比，16 条冲突题的识别从 1 条升到 10 条，策略明确禁令违反从 7/118 降到 1/118。范围内请求放行率从 47.7% 降到 32.0%，所需能力识别 F1 从 0.4638 降到 0.4455。保留题上的取舍和范围失败说明当前双路权重仅适合实验。相同能力还需足够多可区分对象、时间和有效例外的训练例，评估时使用新的保留题。

## 工程验证

两组 checkpoint 保存重载精确一致。现有 22 项回归和 2 项路由与标签测试通过，Docker BuildKit 配置检查无警告。64 token ONNX 在 64 条测试题上和 PyTorch 的所有决策一致，最大绝对 logit 差为 9.06e-6。导出的能力通道按 `requested`、`prohibited`、`scope_overlap` 排列，应用分别做 Sigmoid。手机部署需重新接入新协议、转换 OMC 并做真机 NPU 验证。

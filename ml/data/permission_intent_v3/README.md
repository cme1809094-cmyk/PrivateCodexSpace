# TinyBERT 对照补强数据 v3

这一批针对八个容易混淆的能力补数据：选一张照片／遍历图库、读／写联系人、读／写剪贴板、录像／录音。模型仍输出原字典的全部 32 项能力；Android 与 HarmonyOS 权限映射仍在模型之后处理。

每个场景有两个意思不同的版本 a、b，每个版本再写两种说法，共四条。例如同一业务里“允许录音”和“明确禁止录音”必须得到不同结果。四条作为一组一起进入训练或验证，不能把相似改写分散到两边。

| 用途 | 场景组 | 指令数 | 使用时机 |
| --- | ---: | ---: | --- |
| 新训练数据 | 224 | 896 | 更新模型权重 |
| 新验证数据 | 56 | 224 | 选择轮次、阈值和澄清策略 |
| 独立保留测试 | 70 | 280 | 权重、阈值、策略全部锁定后评估 |

开发数据同时加入“需要澄清”“不需要设备能力”“超出任务范围”的对照。`out_of_scope` 的依据是任务边界，不是某系统没有公共 API；当前八项以外但字典中支持的能力，也不能因此标成超范围。未提及的能力保持 `unmentioned`，不能默认当成禁止。

训练还保留 v2 的开发数据，以覆盖全部 32 项输出。独立复核发现与新验证场景近似的旧训练族、与新训练场景近似的旧验证族，会整族隔离；实际保留数量和 ID 以训练产物的 `training_config.json`、`run_splits.json` 为准。旧测试只用于已知的回归检查。

`development_review.csv` 按组并排显示 a、b 的说法和标注。`reserved_review.csv` 随最终审核包提供。检查者既要看“需要什么能力”，也要看“明确禁止什么”和“是否应先澄清”。

这些指令由 agent 编写，作者自审后再由独立 agent 逐条复核。所有 `human_review` 仍为 `pending`，不代表已经过人工验收。场景组只是一种防泄漏单位，不代表真实用户分布；280 条保留题也不能证明 32 项能力全面达到生产质量。

开发数据检查：

```sh
python3 ml/prepare_intent_contrast_data.py --require-review --render
```

训练脚本不会读取保留题的文本和金标，只校验冻结哈希。比较脚本先验证最终模型锁，再用开发集校准旧版阈值，最后才读取保留题；评测后不据此继续调参。预设实验目标记录在 `experiment_targets.json`，达标情况会逐项如实报告。

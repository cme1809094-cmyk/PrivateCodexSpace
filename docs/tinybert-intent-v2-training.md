# TinyBERT 32能力三态微调

本训练入口使用固定版本的中文TinyBERT 4L底座，读取已生成的权限意图候选数据，进行单句监督微调。输出是32项能力各自的“未提及／需要／明确禁止”，另有正常任务、需要追问、无需设备能力、范围外四类意图判断。

2026-11-18的[训练结果与逐条审阅表](../ml/results/tinybert-intent-v2-20261118/README.md)已归档。选第43轮，内部测试需要F1为44.1%、禁止F1为54.9%，全状态及意图同时正确44/295；尚不足以接管权限判断。三档标准ONNX已通过CPU数值对照，未编译新OMC或更换应用模型。

这份实验与既有五标签应用分开。模型不会生成具体追问句、提取对象/时长/范围槽位，也不会执行系统授权或手机操作。原始语料中的这些限制继续保留，供后续上层处理和人工评估使用。

## 数据与本次划分

先核对原候选文件、独立AI审核报告、32项能力引用及源文件SHA。旧300条参考材料和历史五标签数据不加入本次训练；人工审核状态仍为pending。

原候选750训练、150验证、300测试中，15条训练与5条测试依赖额外上下文。本模型只输入text，因此将这20条单列。

原验证候选缺少ambiguous和no_device_capability。训练入口只用开发数据，从剩余训练候选中各移出三个完整场景族，增加到验证集；保留每项能力的训练正例和完整禁止例。原文件不改，测试成员不改，具体转移ID、SHA和本次运行划分保存在data_manifest.json与run_splits/。

## 模型与训练规则

- 底座：huawei-noah/TinyBERT_4L_zh，revision 152bf15d86715b41dd89c1e03cf5664963d9b005；加载前校验三个原始文件。
- 四层编码器、312隐藏维度；编码器和两个新分类层一起微调。
- 每个能力使用三分类，避免“未提及”和“明确禁止”混在一起。另设四分类意图层。
- 能力层采用按训练频率倒数加权的交叉熵，意图层按训练频率平方根加权；能力损失加上0.5倍意图损失，权重只从训练集计算。初轮较弱的能力平方根权重出现“未提及”偏置，已在测试评估前停止并改用更强的类别平衡。
- 输入长度64 token，超长显式报错，不静默截断。能力标签、状态答案、场景摘要等都不输入模型。
- 默认最大60轮、至少训练25轮，之后连续12轮验证损失无改善则早停；编码器学习率7e-5、分类层3e-4、batch 16、梯度裁剪1.0。
- 每轮只用验证集搜索两项全局门槛，再按0.5倍需要F1、0.35倍禁止F1、0.15倍意图宏F1选择轮次。验证损失只作诊断；新分类层未充分学好时，较低损失可能偏爱“未提及”。最优权重和对应门槛一起保存，测试不参与选择。
- 状态为正常任务时才能输出“需要”；其他状态仍可保留明确禁止。报告同时保留未经过状态约束的原始分类指标，便于发现问题。

主要报告需要/禁止的Precision、Recall、F1、整组状态完全一致率、意图宏F1、过度请求、明确禁止违反率，以及逐能力与逐场景结果。大量“未提及”容易让单一状态准确率显得过高，因此不把它作为核心结论。

## 复现

使用独立训练环境和ml/requirements-training-cpu.txt，不修改CANN环境。固定底座可用原下载器获取：

    python3 ml/fetch_tinybert.py /absolute/path/to/tinybert-source
    python3 -m unittest discover -s tests -p test_intent_training.py -v
    python3 ml/train_permission_intent_v2.py \
      --base /absolute/path/to/tinybert-source \
      --output /absolute/path/to/new-empty-run \
      --epochs 60 --min-epochs 25 --patience 12 \
      --batch-size 16 --threads 4 --seed 20261118

训练结果包含checkpoint/、data_manifest.json、training_config.json、history.jsonl、training_report.json、逐条预测与审核CSV，以及三档标准ONNX和CPU对照向量。输出目录必须是新建或空目录，避免覆盖既有模型。

对新句子运行CPU预测：

    python3 ml/predict_permission_intent_v2.py \
      --checkpoint /absolute/path/to/new-empty-run/checkpoint \
      '录一段视频，但别收音。'

checkpoint采用safetensors保存，重新加载时严格检查权重和标签顺序。源码、底座、数据与产物均保留校验值。

## 导出与部署边界

三档标准ONNX输入为int32的input_ids和attention_mask，固定长度16、32、64；输出分别为capability_logits [1,32,3]与intent_logits [1,4]。各档只用能够完整容纳的测试文本做PyTorch/ONNX Runtime CPU对照，16档覆盖的长句更少，必须看各档实际检查数。

这些输出不能直接替换现有五标签OMC或CPU回退文件。部署需要新增匹配的输出解析、配置、参考向量和模型身份；本次训练不改变应用资源。重新编译OMC时，应重新检查LayerNorm动态范围、FP16一致性、算子NPU绑定和真机自检，不能把旧权重上的修正结果自动视为新模型已经通过。

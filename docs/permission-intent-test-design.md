# 用最简单的话看懂这次的数据和测试

我们要教模型做的事是：听懂一句操作要求，判断需要哪些手机能力、哪些明确不能用、哪里还没说清楚。然后由平台规则把能力转成合适的接口和授权路线。

## 三份题，各有用途

| 材料 | 本轮数量 | 好理解的比喻 | 用途 |
| --- | ---: | --- | --- |
| 训练候选 | 750条，150个场景 | 练习题 | 将来用来教模型理解说法与答案的关系 |
| 验证候选 | 150条，30个场景 | 模拟卷 | 调阈值、选模型、决定什么时候停止训练 |
| 测试候选 | 300条，60个场景 | 正式考卷 | 模型和阈值定下来以后再评分 |
| 原来的参考材料 | 300条 | 讲义 | 保留审阅与定义参考，本轮不混入训练、验证、测试候选 |

合计1500条。这是准备给人审核的原始候选划分，尚未冻结成正式考试。2026-11-18已完成[单句实验性微调](../ml/results/tinybert-intent-v2-20261118/README.md)，本次实际使用705/180/295条：上下文题单列，并从训练候选整族移出30条补齐验证意图类别。原候选文件不改，测试成员未用于调参；内部候选已在开发中观察，不能称为新鲜盲测。将来如果把旧讲义或其他材料也加入训练，必须重新检查有没有泄露测试场景。

## 一道题里装什么

一道题不只是“输入一句话，再贴一个权限名”。它包括：

1. **用户说的话**：例如“录一段视频，但别收音”。
2. **已知背景**：例如是否已经选择文件、是否取消过操作。没有背景就写空，不能凭空补。
3. **标准答案**：需要录像；明确禁止录音；其他能力没提到。
4. **范围限制**：例如只处理这张照片、只执行一次、取消后停止。这些限制不能被误写成禁止整个能力。
5. **是否应该追问**：用户只说“帮我录一下”，就要先问录音还是录像。
6. **出处与审核状态**：记录由哪个AI生成、是否交叉复核、人审是否完成。

机器文件中的主要字段对应如下：

| 字段 | 大白话 |
| --- | --- |
| text | 用户原话 |
| context | 真正提供给处理流程的背景 |
| required_capabilities | 这件事需要什么能力 |
| forbidden_capabilities | 用户明确禁止哪些完整能力 |
| default_state_for_other_capabilities | 其他能力一律“没提到” |
| constraints | 对对象、次数、时长、方式等的限制 |
| intent_status / needs_clarification | 属于可识别任务、没说清楚、无需设备能力，还是当前范围外；要不要问一句 |
| family_id / split_candidate | 属于哪个场景，候选放进哪份题 |
| review | AI复核和人工审核分别进行到哪一步 |

“需要”不等于已经拿到系统权限，“没提到”也不等于禁止。平台所需的附加权限由字典解释，不因为接口需要定位权限，就把用户的“扫描Wi-Fi”擅自改标成“要求获取精确位置”。

考试时，模型只能看到用户原话和明确允许提供的背景。能力标签、范围答案、追问答案、场景摘要等都只给判卷程序或审核人员看，不能一起塞给模型，否则等于把答案印在题目上。

## 为什么不能把所有句子随便打乱

假设有五句话：“录视频不要声音”“拍段无声视频”“只录像别开麦”……它们可能只是同一个场景的五种说法。

如果把前三句用来训练，最后两句拿来测试，模型很可能只是记住了熟悉题型。考试成绩会很好看，但不能说明它会处理新场景。

这次先把每个场景的五种说法绑在一起，再把整个场景放进一份题。改一个人名、日期或设备名称，不足以算新场景。测试场景要在动作、对象范围、条件或上下文模式上有实质差别。

程序会检查相同文本与背景、同一场景是否跨集合、标注是否冲突，并筛出跨集合的近似说法；独立AI再看语义有没有“换皮漏题”。不同场景ID和低文字相似度都不能单独证明没有泄漏，所以还保留人工审核步骤。

300条测试候选实际上来自60个场景。以后汇报时要同时报句子成绩和场景成绩，不能把五个近似改写当五道完全独立的题来夸大可信度。

## 怎么判断答得好不好

下面是帮助理解的示例，不是本轮模型的实测结果：

| 用户要求 | 应该答什么 | 重点查什么 |
| --- | --- | --- |
| 录一段视频，但别收音 | 需要录像；禁止录音 | 是否多要了麦克风 |
| 用系统选图器选一张照片 | 只需要选一张照片 | 是否误判成读整个相册 |
| 查杭州明天的天气，不要定位手机 | 不需要设备定位；明确禁定位 | 是否看到“天气”就要定位 |
| 帮我录一下 | 先问录音还是录像 | 是否擅自猜一种能力 |
| 只看已有网络缓存，不重新扫描 | 处理缓存，禁止本次主动扫描 | 是否把处理已有数据误判成调用扫描 |

评分要同时看四件事：

- **漏没漏**：需要两项能力，却只找出一项。
- **多没多**：只需要选一张照片，却要求读取全相册。
- **有没有违背明确禁止**：用户不让录音，却预测需要麦克风。这类错误要单独统计。
- **该问时会不会问**：不明确的要求先追问，明确的要求别反复追问。

技术报告可以给出需要能力的Precision/Recall/F1、整句能力集合完全正确率、明确禁止违反率、意图类别准确率和追问的Precision/Recall，同时按能力、场景族和难题类别拆开看。不能只给一个平均分，把“多要权限”藏在里面。

三份候选都包含32项能力的正例，新增1200条整体也覆盖各项明确禁止；但300条测试候选尚未给每项能力都配齐明确禁止题，缺项记录在test_set_overview.json。正式冻结前还要补平这些覆盖，不能用已有禁止题的成绩代表所有能力。

范围、时长、身份、顺序等限制目前以文字记录。只有将来处理流程真正支持这些输出，或另配人工判卷规则后，才能给它们计算可靠成绩；不能用自由文本字面匹配冒充理解正确。

## 有些题要带背景才能考

带有context_required标记的题，标准答案依赖额外背景。评测时必须把背景真实提供给模型或上层处理流程。

如果目前模型只能接收一句话，这类题先单列，不能偷偷使用背景判卷，也不能把它们算成纯文本模型的失败。相同原话在不同背景下产生不同答案，本身可以是有价值的对照测试。

本轮还用应用真实分词逻辑和两份配套词表检查了长度：1500条原话都能放进现有64 token档，最长为55 token，包含句首句尾标记。这只说明句子放得下，不代表当前模型已经会答；如果未来把背景也拼进输入，需要重新检查长度，不能静默截掉重要否定词。

## 现在的边界

当前Demo仍是既有五标签模型；本轮没有将其自动变成32能力模型。新语料还包括否定、上下文、追问与范围限制，未来可能由分类模型和上层规则共同处理，不意味着现有模型已能直接输出这些字段。

旧模型的训练材料还存在另一种边界：以前“读取联系人、扫描蓝牙”算范围外，现在已经纳入新能力。所以旧五标签答案不能直接混入这轮训练。程序会检查新句子是否与历史163条材料存在文字重复，但这不证明它们在语义上或模型历史训练上完全独立；正式验收还要审查所用模型的训练来源。

这批材料主要由AI合成并做AI交叉复核，人工审核仍待完成，不能当作真实用户总体分布，也不是已经通过的产品准确率验收。正式冻结测试集前还需要人工核对、补充真实使用场景、确认输入输出能力并锁定版本。看过测试错题后修改模型，会消耗这份测试集的独立性；后续正式验收应再保留一份新题。

还要分清两场考试：**文字理解测试**检查意图答得对不对；**NPU自检**检查手机计算结果是否与参考结果一致。NPU自检全过，不代表模型听懂了用户；模型语义答对，也不代表手机NPU部署已经通过。
